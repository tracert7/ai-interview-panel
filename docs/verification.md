# 검증 기록 · 2026-10-18

## v0.5.1 — 마이크 연결 표시·대기 복구

- 실제 내장 브라우저에서 `network`에 대응하는 음성 인식 연결 실패 안내를 확인했습니다. 이는 `audio-capture`나 권한 거부가 아니며, 이 관찰만으로 장치 고장이나 특정 네트워크 원인을 확정하지 않았습니다.
- 기존 코드는 `start()` 호출 전에 듣기 상태를 표시했습니다. 이를 연결 요청/듣기/마무리로 분리하고, 브라우저 `start` 또는 `audiostart` 이벤트가 온 뒤에만 듣기 표시를 켭니다. 시작 신호가 없는 경우 12초 연결 대기 타이머로 중단하며 자동 재시도하지 않습니다.
- 연결 전 취소·빈 인식 결과는 성공한 음성 입력으로 표시하지 않습니다. 기존 답변은 네트워크 오류나 취소 뒤에도 보존됩니다. 유료 음성 API나 새 계정 권한을 추가하지 않았습니다.
- **자동 테스트 39개 통과, 실패 0개**. 실제 시작 전 표시, 시작 신호 후 전환, 연결 시간 초과, 늦게 도착한 이벤트 무시, 빈 세션 종료, 연결 취소, 네트워크 실패 뒤 답변 유지 등을 확인했습니다. 이벤트 모의 시험은 실제 발화 검증과 다릅니다.
- Chrome 실제 검수 도중 연결 타이머의 `Illegal invocation` 호출 오류를 추가로 발견했습니다. 기본 타이머를 안전한 래퍼로 감싸고, Window 메서드의 잘못된 receiver를 검출하는 회귀 시험을 추가했습니다. 수정 뒤 Chrome에서 12초 대기 안내와 연결 중단을 실제 확인했습니다. 사용자는 이후 마이크 권한 요청을 직접 허용했다고 알려왔습니다.
- 일반 Chrome에서 기존 구독 연결·모델 선택·몰입 화면 진입·연결 요청 표시를 확인했습니다. 사용자가 마이크 권한을 직접 허용한 뒤, 실제 시작 신호와 실제 발화 텍스트 55자가 화면에 들어오는 것을 확인했습니다. 녹음 파일은 저장하지 않았습니다.
- 자작 가상 문장의 ‘24건을’이 ‘24권의’, ‘구분을’이 ‘9분에’로 인식되어, 주어진 문장에 근거해 오인식을 교정했습니다. 57자 답변으로 화면의 평가 버튼을 눌러 인사 15·현업 12·팀장 15점(각 20점 만점), 원문 근거·보완점·꼬리질문·기록을 확인했습니다. 짧은 가상 답변의 기능 시험이며 실제 채용 결과·다른 답변과의 실력 비교에 사용하지 않습니다.
- 이 Chrome 환경에서는 **실제 음성 → 텍스트 검수 → 실제 구독 평가**까지 확인했습니다. 내장 브라우저나 모든 장치에서의 지원·인식 정확도를 보장하지 않으며, 단어 오인식 검수는 필요합니다.
- 참고: [시작 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/start_event), [오디오 시작 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/audiostart_event), [오류 구분](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognitionErrorEvent/error).

## v0.5.0 — 면접 입장형 → 몰입 면접형

- 사용자가 추천한 두 시안의 조합을 선택했습니다. 준비 화면은 직무·선택 첨부·전송 동의·시작, 면접 화면은 큰 면접실과 질문·음성 답변으로 분리했습니다. 연결·모델은 모달로 옮겼습니다.
- Work 요청문 메뉴·복사·TXT 다운로드·요청문 생성 함수를 제거했습니다. 과거 실제 실습 기록과 점수는 예제 출처로 보존하며 새 답변 평가와 구분합니다.
- **자동 테스트 35개 통과, 실패 0개**. 서류가 있으면 시작 클릭 뒤 질문 생성 1회 → 첫 질문으로 자동 입장, 없으면 생성 요청 없이 기본 질문으로 입장하는 흐름을 확인했습니다. 실패하면 입장 화면에 남고 자동 재시도하지 않습니다.
- 직무·모델·전송 동의가 없을 때 차단, 마이크 자동 시작 없음, 음성 입력 완료 전 평가 버튼 감춤, 준비/면접 왕복 시 답변 유지, 예제에서 내 입력 복원도 DOM 테스트로 확인했습니다.
- 실제 계정으로 새로 AI 요청을 반복하지 않았습니다. v0.4.0에서 실제 확인한 같은 서류 질문·평가 엔드포인트를 유지했으며 v0.5.0의 화면 연결은 가상 전송 테스트로 검증했습니다.
- 브라우저 제어 연결이 시간 초과되어 **375/768/1440px 실제 렌더와 실제 마이크 발화는 확인하지 못했습니다**. DOM/스타일 소스 검사는 화면·장치 E2E 검수와 다릅니다. 이미지·역할·응답 데이터는 실제 앱의 기존 자산을 사용했습니다.

## v0.4.0 — 서류 기반 질문·음성 텍스트 입력

- UI 방향은 사용자 선택인 픽셀 면접실을 유지했습니다. GitHub의 frontend-design 스킬과 UI/UX Pro Max를 참고해 연결/공고 설정을 접고, 서류 준비·질문·음성 답변·피드백의 순서를 정리했습니다.
- **자동 테스트 33개 통과, 실패 0개**. 이전 22개 회귀 검증에 문서 추출·원문 인용·음성 이벤트·DOM UI 흐름·PDF 자원 경로 제한 11개를 추가했습니다. 파일 선택 뒤 AI 자동 전송 없음, 마이크 시작 전 동의, 최종 인식만 추가, 중복 방지, 정지·권한 오류, 서류 수정 시 동의 재확인을 시험했습니다.
- 자작 가상 한국어 TXT·DOCX와 가상 영문 텍스트 PDF를 실제 파서로 읽었습니다. PDF 쪽수 표기, 빈/스캔형·손상 문서 실패, 미지원 확장자·경로·DTD·크기 제한도 확인했습니다. 모든 PDF 레이아웃이나 한글 OCR을 검증한 것은 아닙니다.
- 실제 승인된 ChatGPT 구독 연결의 **GPT-6.1 Sol**로 자작 가상 지원서(348자)의 질문 1회, 답변 평가 3회를 실행했습니다. 실제 이력서·사용자 문서는 읽지 않았습니다.
- 인사·현업·팀장 질문이 1개씩 반환됐고 파일명과 원문 인용이 모두 실제 전달 본문과 일치했습니다. 인사 질문은 분류 경험과 지원 동기, 현업 질문은 측정 결과와 미측정 전환 효과의 구분, 팀장 질문은 본인 역할과 공동 결정·향후 계획의 구분을 물었습니다.
- 같은 가상 답변의 세 역할 평가는 모두 18/20점이었습니다. 원문 인용·다섯 점수·합계를 대조했습니다. 이 점수는 채용 판단·합격률이나 다른 지원자의 예상 점수가 아닙니다.
- 질문 요청 입력/출력 토큰 715/516, 평가 세 개 합계 입력/출력 2,760/833이었습니다. 단일 전체 확인은 약 31.8초였고 중간 3.1초 중복 요청 방지 대기도 포함됩니다. 속도·절약률로 일반화하지 않습니다.
- API 키나 별도 유료 전사 API를 사용하지 않았습니다. 구독 사용량을 소비하며 사용자가 이미 허용한 크레딧 정책은 바꾸지 않습니다.
- **실제 마이크 음성 인식 및 375/768/1440px 시각 렌더 검수는 미완료**입니다. 브라우저 자동 연결이 응답하지 않았습니다. 음성 이벤트/DOM 테스트는 실제 발화·브라우저 권한·레이아웃 E2E 검증과 다릅니다. 사용자가 본인 브라우저에서 마이크 권한을 허용하고 직접 확인해야 합니다.

실제 재확인이 필요한 개발자는 `node scripts/check-subscription-documents.mjs --run-live --model <현재 계정 모델>`로 같은 자작 가상 사례를 사용할 수 있습니다. 실행하면 구독 요청 4회를 사용하며 자동 재시도하지 않습니다.

## v0.3.0 — PC 실행 + ChatGPT 구독 로그인

- 사용자가 OpenAI 로그인과 앱의 구독 사용을 직접 승인했습니다. 기존 ChatGPT·Codex 로그인 파일은 사용하지 않았습니다.
- 로컬 앱에서 로그인·구독 권한이 모두 확인됐고, 계정의 모델 목록을 공식 모델 엔드포인트에서 받았습니다.
- Windows 로컬 서버를 재시작한 뒤에도 새 로그인 없이 연결·구독 권한과 모델 목록이 유지되는 것을 확인했습니다. 암호화된 토큰 자체는 화면·로그·검증 문서에 출력하지 않았습니다.
- 새로 받은 OAuth 권한으로 **GPT-6.1 Sol**에 가상 답변 한 개를 역할별 요청 세 개로 실제 평가했습니다. 인사 10점, 현업 12점, 팀장 10점(각 20점 만점)이 반환됐으며 오류는 없었습니다.
- 각 결과는 실제 답변의 인용문, 다섯 점수, 합계, 보완점, 꼬리질문 형식을 통과했습니다. 합계는 코드로 재검산했습니다.
- 이 단일 실행에서 세 요청의 입력 토큰 합계는 2,229개, 출력은 915개였습니다. 소요 시간은 약 11.6초였으나 모델·계정·입력에 따라 달라집니다. API 가격으로 구독 사용량을 환산하지 않았습니다.
- 별도 API 키·과금 계정·자동 결제 우회는 사용하지 않았습니다. 구독 사용량 또는 계정에서 허용한 크레딧의 적용 범위는 사용자가 ChatGPT 설정에서 관리합니다.
- 로컬 앱 API로 실제 연결을 시험했습니다. 브라우저 자동 제어가 응답하지 않아 새 로그인 패널의 모든 UI 동작을 자동 브라우저 E2E로 검증했다고 주장하지 않습니다. 로그인·권한 승인은 사용자 직접 조작, 실제 평가는 로컬 앱의 정상 요청 경로로 확인했습니다.

## 기존 실습 기록

2026-10-18의 가상 공고·경험으로 ChatGPT Work 실제 서브에이전트 3개에서 두 답변을 평가한 별도 기록도 유지합니다. Work 기록의 첫 점수는 12·11·11점, 수정 후는 19·18·19점이었습니다. 이 값은 로컬 앱의 새 답변 점수가 아니며 현재 계정에서 재현을 보장하지 않습니다.

픽셀 면접실은 이전 버전에서 데스크톱과 좁은 화면의 배치·역할 선택·답변 뒤 피드백 열림을 확인했습니다. 새 로그인 연결의 범위와 섞어 모든 기기·계정의 UI가 검증됐다고 표현하지 않습니다.

## 검증하지 않은 것

실제 지원자의 채용 결과, 공정한 채용 검사로서의 타당성, 합격 확률, 음성·시선·표정 분석, 모든 구독·워크스페이스·운영체제의 로그인, 장기 만료·장애 상황의 실계정 재현은 검증하지 않았습니다. 토큰 갱신과 장애 복구는 가짜 자격증명 테스트로 확인했습니다. 평가 점수는 답변을 고치기 위한 연습용 의견입니다.
